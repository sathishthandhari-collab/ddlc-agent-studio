## 1. Document Purpose & Architectural Pivot

The Meta-Agent's Documentarian outputs structured YAML implementation documents (`impl_docs/`): `agent.yaml`, `stages/*.yaml`, `contracts/*.yaml`, `config.yaml`, and `tests.yaml`. 

This document defines how the **Builder Specialist** (Phase 6 of the Meta-Agent workflow) transforms those implementation documents into a deployable, production-ready Python codebase for a **Layer 2 DDLC AI Agent** (such as the canonical `dbt_pipeline_builder_agent`).

### 1.1 The Architectural Pivot: Split Compiler + Leaf Coder

Earlier conceptual drafts envisioned the Builder as a single, large-language-model-driven code generator that ingested all implementation documents and outputted Python files via iterative LLM prompts. 

Just as the **DCM Schema Engine** ([`dcm_agent.md`](file:///s:/DATA/agents/ddlc-agent-studio/design-docs/dcm-agent/dcm_agent.md)) rejected LLM-based SQL generation in favor of a 100% deterministic **SQLGlot + Alembic** compiler, **we explicitly split the Builder Specialist into two distinct architectural tiers**:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                BUILDER SPECIALIST (PHASE 6)                            │
│                                                                                        │
│   ┌────────────────────────────────────────────────────────────────────────────────┐   │
│   │                 TIER 1: DETERMINISTIC SCAFFOLD COMPILER                        │   │
│   │                          (Jinja2 + Python AST)                                 │   │
│   │                                                                                │   │
│   │  • Zero LLM calls. Pure, instantaneous Python compilation.                     │   │
│   │  • Emits the complete read-only orchestration skeleton.                        │   │
│   │  • Compiles Instructor Pydantic models from contracts/*.yaml, StateGraph DAG,  │   │
│   │    ToolNode bindings, reflection retry loops, interrupt() human review gates,  │   │
│   │    and Tier 1/2 metadata framework callbacks.                                  │   │
│   │  • Header: # DO NOT EDIT. Autogenerated deterministically by DDLC Compiler.    │   │
│   └───────────────────────────────────────┬────────────────────────────────────────┘   │
│                                           │ identifies bespoke tools                   │
│                                           │ (processing.tools[].handler)               │
│                                           ▼                                            │
│   ┌────────────────────────────────────────────────────────────────────────────────┐   │
│   │                    TIER 2: LLM LEAF CODER & TEST SYNTHESIZER                   │   │
│   │                     (Instructor + Structured Output Prompts)                   │   │
│   │                                                                                │   │
│   │  • Invoked ONLY for stages requiring custom imperative tools or verifiers.     │   │
│   │  • Scoped strictly to leaf functions (e.g. tools/sqlglot_verifier.py).         │   │
│   │  • Synthesizes editable tools (src/tools/*.py), prompt templates, and tests.   │   │
│   │  • Regular, version-controlled Python code: editable by Meta-Agent or humans.  │   │
│   └────────────────────────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 Rationale: Why Split the Builder?

| Engineering Concern | All-LLM Code Generation (Rejected) | Deterministic Compiler + LLM Leaf Coder (Selected) |
|---|---|---|
| **Determinism & Syntax Reliability** | LLMs occasionally hallucinate import paths, invert conditional branching, misplace retry arguments, or introduce subtle indentation syntax errors in complex LangGraph state machines. | **Mathematical Determinism**: The orchestration skeleton is compiled via Jinja2 templates verified by Python `ast.parse`. Syntax is 100% guaranteed. |
| **Contract Fidelity & Schema Typing** | LLMs may drop optional attributes, alter field types, or fail to conform to Instructor Pydantic schemas. | **Deterministic AST Compilation**: `contracts/*.yaml` compiles directly into Pydantic v2 data models used by Instructor for structured LLM reasoning and node boundary validation. Zero schema drift. |
| **Token Cost & Latency** | Generating thousands of lines of boilerplate scaffolding (graphs, contracts, config, logging) consumes ~25,000–50,000 output tokens and takes 60–90 seconds per run. | **Sub-Second Scaffold Emission**: The scaffold compiler runs locally in <250ms with zero API token consumption. LLM tokens are spent solely on bespoke business logic (~500 tokens). |
| **Maintainability (The "2 AM Bug" Rule)** | When an agent fails in production at 2 AM, on-call engineers cannot easily debug a monolithic 1,200-line generated agent script where state wiring, logging, and logic are intertwined. | **The Skeleton vs. The Muscle**: The orchestration skeleton is immutable and verified. On-call engineers can inspect and hotfix `src/tools/sqlglot_verifier.py` directly without fear of breaking graph transitions. |
| **Day-2 Change Requests** | Changing a single model attribute or retry threshold in an all-LLM system requires regenerating the entire agent codebase, risking regression across unrelated stages. | **Surgical Recompilation**: Schema or retry changes re-run only the deterministic compiler. Leaf tools and prompt templates remain untouched. |

## 2. Core Paradigm: "The Skeleton" vs. "The Muscle"

The generated codebase enforces a strict separation of concerns between **structural orchestration** and **imperative execution**.

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              GENERATED AGENT CODEBASE                                  │
│                                                                                        │
│  ┌──────────────────────────────────────────────────────────────────────────────────┐  │
│  │                    THE SKELETON (100% Read-Only, Deterministic)                  │  │
│  │                                                                                  │  │
│  │  # DO NOT EDIT. Autogenerated deterministically by DDLC Compiler from impl_docs. │  │
│  │                                                                                  │  │
│  │  • src/models/contracts_pydantic.py (Pydantic v2 / Instructor contracts)         │  │
│  │  • src/core/config.py               (Pydantic BaseSettings & secrets resolution) │  │
│  │  • src/core/telemetry.py            (Tier 1/2 metadata callback listener)        │  │
│  │  • src/graph.py                     (StateGraph wiring, tool loops, gates)       │  │
│  │  • tests/contracts/test_contracts.py(Contract schema conformance test suite)     │  │
│  └──────────────────────────────────────────┬───────────────────────────────────────┘  │
│                                             │ invokes via dynamic dispatch             │
│                                             ▼                                          │
│  ┌──────────────────────────────────────────────────────────────────────────────────┐  │
│  │                    THE MUSCLE (Editable, LLM or Human Authored)                  │  │
│  │                                                                                  │  │
│  │  # Editable tools and prompt templates — hotfixable by engineers or Meta-Agent   │  │
│  │                                                                                  │  │
│  │  • src/tools/db_inspector.py        (Bespoke catalog discovery tool)             │  │
│  │  • src/tools/sqlglot_verifier.py    (Bespoke AST syntax validation tool)         │  │
│  │  • src/prompts/*.jinja2             (Domain-specific Jinja2 prompt templates)    │  │
│  │  • tests/unit/test_sqlglot_verifier.py (Targeted unit tests & edge case mocks)   │  │
│  └──────────────────────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 The Skeleton (Read-Only)
- **Source**: Compiled directly from `agent.yaml`, `stages/*.yaml`, `contracts/*.yaml`, and `config.yaml`.
- **Role**: Defines the agent state machine, data transfer contracts, LiteLLM client initialization, reflection retry loops, human review gates, and metadata framework interception.
- **Mutability**: **Immutable**. Sealed with an autogenerated header. CI blocks pull requests that modify skeleton files without corresponding `impl_docs/` changes.
- **Standard Tools**: Standard I/O (e.g., LiteLLM client, Postgres checkpointer) and Tier 2 shared components (e.g., `schema_inspector_v1`, `git_deliverer_v1` declared with `type: shared_component`) are emitted directly into the skeleton using hardened SDK boilerplate.

### 2.2 The Muscle (Editable Tools & Prompts)
- **Source**: Synthesized by the LLM Leaf Coder during Phase 6, or authored directly by engineers.
- **Role**: Houses domain-specific imperative tools (e.g., custom database inspectors, AST verifiers, API connectors) and externalized Jinja2 prompt templates.
- **Interface**: Plugged into the skeleton via standardized, typed tool handler signatures (`processing.tools[].handler`).
- **Mutability**: **Fully Editable**. Version-controlled Python code and Jinja2 templates. Human developers or the Meta-Agent can refactor, optimize, or hotfix these functions without altering the state graph.

## 3. The Deterministic Scaffold Compiler

The Deterministic Scaffold Compiler is a pure Python engine located in `src/specialists/builder/compiler/`. It parses YAML implementation documents and renders pre-tested Jinja2 templates into Python ASTs, validating syntax before writing files to disk.

```
┌─────────────────────────────────┐
│           impl_docs/            │
│                                 │
│  • agent.yaml                   │
│  • stages/*.yaml                │
│  • contracts/*.yaml             │
│  • config.yaml                  │
│  • tests.yaml                   │
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│  Scaffold Compiler (Jinja2)     │
│                                 │
│  1. Ingests & validates YAML    │
│  2. Selects runtime template    │
│  3. Compiles Instructor models  │
│  4. Compiles config loaders     │
```

### 3.1 Contract Compilation (`contracts/*.yaml` → Instructor Pydantic Models)

Every contract file in `contracts/<name>.yaml` is compiled deterministically into Pydantic v2 data models in `src/models/contracts_pydantic.py`. These models serve as:
1. **Agent State Contracts**: Typed objects passed between nodes in LangGraph `AgentState`.
2. **Structured LLM Output Contracts**: Enforced at runtime via Instructor (`client.chat.completions.create(response_model=TransformationPlan)`), guaranteeing that LLM reasoning conforms strictly to the schema.
3. **Automated Schema Test Suites**: Emitted in `tests/contracts/test_contracts.py`.

### 3.2 Configuration Compilation (`config.yaml` → Pydantic `BaseSettings`)

The compiler reads `config.yaml` and produces `src/core/config.py`:
- Emits nested Pydantic models matching the YAML hierarchy with `env_nested_delimiter="__"` so `${config.a.b.c}` maps deterministically to `settings.a.b.c`.
- Inherits framework-level state and telemetry configurations (`CHECKPOINTER_DB_URI`, `METADATA_DB_URI`) from a standard `FrameworkRuntimeSettings` mixin.
- Generates structured configuration classes for external endpoints (`sources`, `destinations`, `dbt`, `llm`).
- Emits secret resolvers that pull from environment variables or AWS Secrets Manager / HashiCorp Vault.
- Guarantees **Zero Hardcoded Secrets or URIs**.

### 3.3 Telemetry & Operational Metadata (Decoupled Telemetry vs. Transactional Delivery)

Following the architecture established in [`01_metadata_framework.md`](file:///s:/DATA/agents/ddlc-agent-studio/design-docs/metadata-framework/01_metadata_framework.md) (Section 6.2 and Decisions 8 & 30), generated agents **do not embed manual telemetry decorators inside stage functions**, but strictly decouple passive operational telemetry from transactional delivery writes:

1. **Passive Telemetry (Observability Spans & Gate Audits)**:
   - Automatically captured via LangGraph callback handlers (`MetadataCallbackHandler`) attached to the `StateGraph` runner.
   - Intercepts node execution, timing, LLM token counts, model pricing, error traces, and gate events (`stage_gate_record`, `decision_log`).
   - Writes directly to Tier 1 tables (`agent_metadata.agent_run_header`, `agent_metadata.execution_log`, `agent_metadata.decision_log`).
   - Non-intrusive: Specialists and leaf logic never make manual telemetry calls. If telemetry logging encounters an issue, it logs an observability warning without corrupting graph execution state.

2. **Transactional Delivery Writes & Asset Registration (Explicit Delivery Node)**:
   - Executed within the **explicit deterministic delivery node** (`node_deliver_stage` in Layer 2; Phase 8 Delivery in Layer 1 Meta-Agent).
   - Commits generated artifacts to Git, creates Pull Requests, writes model manifests and contract dependencies into `ddlc_shared_metadata.contract_lineage`, and registers agent versions in `ddlc_shared_metadata.agent_registry`.
   - Emits the validated `DeliveryManifest` contract into `state["contracts"]["delivery_manifest"]`.
   - **Fail-Fast Semantics**: Because this is a critical business transaction, failures (e.g. Git authentication errors, database constraint violations) are never swallowed by callback handlers. They raise explicit exceptions, update diagnostics, and halt completion.

## 4. The Two Runtime Generation Strategies

The compiler supports two distinct runtime strategies configured in `agent.yaml` (`architecture.runtime`):

```yaml
architecture:
  runtime: "langgraph" # Options: langgraph | python_litellm
```

### 4.1 Strategy 1: LangGraph (`langgraph`)

Designed for stateful agent workflows requiring multi-step reasoning, tool-calling loops, self-correction reflection edges, and human review gates.

#### StateGraph Skeleton Wiring
- **State Definition**: Defines `AgentState` containing typed contract dictionaries, run metadata, reflection retry counters, and error diagnostics.
- **Claim Check for Artifacts**: While intermediate schemas fit comfortably in memory, large engineering artifacts (e.g. multi-file dbt bundles, generated tarballs) use lightweight Claim Check pointers (`bundle_id`, `uri`, `artifact_sha256`) to ensure PostgreSQL checkpointer snapshots remain sub-millisecond.
- **Node Emission**: Wraps each stage in an orchestration node function. LLM reasoning nodes use LiteLLM + Instructor to emit validated contracts. Tool nodes execute bound `@tool` functions.
- **Self-Correction Reflection Edges**: On compilation or lint failures in sandbox testing, deterministic conditional edges route back to the LLM generation node with diagnostic error logs (up to `safety_valves.max_reflection_retries`).
- **Human Approval Gates**: For stages declared with `autonomy: human_required` (e.g., the `review` stage), the compiler inserts LangGraph `interrupt()` calls. The human reviewer inspects the generated artifacts before execution resumes to open a Git PR.

```python
# ==============================================================================
# DO NOT EDIT. Autogenerated deterministically by DDLC Compiler from impl_docs.
# File: src/graph.py
# ==============================================================================
import os
import uuid
import hashlib
from typing import TypedDict, List, Dict, Any, Optional
from jinja2 import Environment, FileSystemLoader, StrictUndefined
import instructor
import litellm
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.postgres import PostgresSaver
from langgraph.types import interrupt
from ddlc_metadata.callbacks import MetadataCallbackHandler
from src.core.config import settings
from src.models.contracts_pydantic import (
    SourceSchemaProfile, TransformationPlan, DbtArtifactBundle, GeneratedFileSet, DeliveryManifest
)
from src.tools.db_inspector import inspect_information_schema
from src.tools.sqlglot_verifier import validate_sql_ast
from src.tools.git_deliverer import publish_dbt_pull_request, register_pipeline_delivery

# Configure Instructor with LiteLLM
client = instructor.from_litellm(litellm.completion)

# Configure Jinja2 prompt template loader with StrictUndefined to prevent silent misses
jinja_env = Environment(
    loader=FileSystemLoader("src/prompts"),
    autoescape=False,
    undefined=StrictUndefined
)
plan_prompt_tmpl = jinja_env.get_template("stage_plan.jinja2")
generate_prompt_tmpl = jinja_env.get_template("stage_generate.jinja2")

class AgentState(TypedDict):
    run_id: str
    contracts: Dict[str, Any]
    reflection_count: int
    diagnostics: List[str]
    human_approved: bool
    review_decision: Optional[str]

def node_discover_stage(state: AgentState) -> Dict[str, Any]:
    """Deterministic tool execution node: introspects source database catalog."""
    raw_profile = inspect_information_schema(
        connection_uri=settings.sources.postgres_oltp.uri, schema=settings.sources.postgres_oltp.schema_name
    )
    profile = SourceSchemaProfile.model_validate(raw_profile)
    return {
        "contracts": {**state["contracts"], "source_schema_profile": profile.model_dump()},
        "reflection_count": 0
    }

def node_plan_stage(state: AgentState) -> Dict[str, Any]:
    """LLM Reasoning node: plans dbt staging and marts architecture."""
    profile = SourceSchemaProfile.model_validate(state["contracts"]["source_schema_profile"])
    
    # Universal Prompt Contract injection: input, diagnostics, feedback, config
    human_feedback = [d.replace("Reviewer feedback: ", "") for d in state.get("diagnostics", []) if d.startswith("Reviewer feedback:")]
    compiler_diagnostics = [d for d in state.get("diagnostics", []) if not d.startswith("Reviewer feedback:")]
    
    prompt_content = plan_prompt_tmpl.render(
        input=profile,
        diagnostics=compiler_diagnostics,
        feedback=human_feedback,
        config={"target_dialect": "snowflake", "project_name": "analytics_dbt"}
    )
    
    plan: TransformationPlan = client.chat.completions.create(
        model=settings.llm.model_tiers.reasoning,
        response_model=TransformationPlan,
        messages=[
            {"role": "system", "content": "You are an expert analytics engineer. Design a clean dbt project structure."},
            {"role": "user", "content": prompt_content}
        ],
        temperature=0.1
    )
    return {
        "contracts": {**state["contracts"], "transformation_plan": plan.model_dump()}
    }

def node_generate_stage(state: AgentState) -> Dict[str, Any]:
    """LLM Code Generation node with reflection feedback, followed by deterministic file staging."""
    plan = TransformationPlan.model_validate(state["contracts"]["transformation_plan"])
    
    # Partition diagnostics between automated tool errors and human reviewer comments
    human_feedback = [d.replace("Reviewer feedback: ", "") for d in state.get("diagnostics", []) if d.startswith("Reviewer feedback:")]
    compiler_diagnostics = [d for d in state.get("diagnostics", []) if not d.startswith("Reviewer feedback:")]

    # Universal Prompt Contract injection: input, diagnostics, feedback, config
    prompt_content = generate_prompt_tmpl.render(
        input=plan,
        diagnostics=compiler_diagnostics,
        feedback=human_feedback,
        config={"target_dialect": plan.target_dialect, "sandbox_dir": settings.dbt.sandbox_project_dir}
    )
    
    messages = [
        {"role": "system", "content": "Synthesize production dbt SQL models and schema.yml tests."},
        {"role": "user", "content": prompt_content}
    ]

    # 1. LLM synthesizes structured file set (The Muscle)
    file_set: GeneratedFileSet = client.chat.completions.create(
        model=settings.llm.model_tiers.reasoning,
        response_model=GeneratedFileSet,
        messages=messages,
        temperature=0.0
    )

    # 2. Deterministic node stages files to disk & builds Claim Check pointer (The Skeleton)
    bundle_id = str(uuid.uuid4())
    bundle_dir = os.path.join(settings.dbt.sandbox_project_dir, bundle_id)
    os.makedirs(bundle_dir, exist_ok=True)

    manifest: List[str] = []
    hasher = hashlib.sha256()

    for file_entry in file_set.files:
        file_path = file_entry.path.lstrip("/\\")
        full_path = os.path.join(bundle_dir, file_path)
        os.makedirs(os.path.dirname(full_path), exist_ok=True)
        content_bytes = file_entry.content.encode("utf-8")
        with open(full_path, "wb") as f:
            f.write(content_bytes)
        manifest.append(file_path)
        hasher.update(file_path.encode("utf-8"))
        hasher.update(content_bytes)

    bundle = DbtArtifactBundle(
        bundle_id=bundle_id,
        storage_uri=bundle_dir,
        file_manifest=manifest,
        artifact_sha256=hasher.hexdigest(),
    )

    return {
        "contracts": {**state["contracts"], "dbt_artifact_bundle": bundle.model_dump()},
        "diagnostics": []
    }

def node_dry_run_stage(state: AgentState) -> Dict[str, Any]:
    """Sandbox testing node: executes SQLGlot lint and dbt compile."""
    plan = TransformationPlan.model_validate(state["contracts"]["transformation_plan"])
    bundle = DbtArtifactBundle.model_validate(state["contracts"]["dbt_artifact_bundle"])
    errors = []
    
    # In claim_check mode, read generated models from bundle storage_uri
    for file_path in bundle.file_manifest:
        if file_path.endswith(".sql"):
            full_path = os.path.join(bundle.storage_uri, file_path)
            if os.path.exists(full_path):
                with open(full_path, "r", encoding="utf-8") as f:
                    sql_content = f.read()
                is_valid, err_msg = validate_sql_ast(sql_content, dialect=plan.target_dialect)
                if not is_valid:
                    errors.append(f"{file_path}: {err_msg}")
            
    return {
        "diagnostics": errors,
        "reflection_count": state.get("reflection_count", 0) + (1 if errors else 0)
    }

def route_dry_run(state: AgentState) -> str:
    """Deterministic routing edge: self-correction reflection vs human review gate."""
    if state["diagnostics"]:
        if state["reflection_count"] < 3:
            return "generate_stage"  # Loop back to LLM with error feedback
        return "review_stage"        # Escalate to human if retries exhausted
    return "review_stage"

def node_review_stage(state: AgentState) -> Dict[str, Any]:
    """Human review gate: halts with LangGraph interrupt(), passes Claim Check pointer, resumes on decision."""
    bundle = state["contracts"]["dbt_artifact_bundle"]
    approval_payload = interrupt({
        "task": "review_dbt_models",
        "bundle_id": bundle["bundle_id"],
        "storage_uri": bundle["storage_uri"],
        "file_manifest": bundle["file_manifest"],
        "artifact_sha256": bundle["artifact_sha256"],
        "diagnostics": state.get("diagnostics", [])
    })
    decision = approval_payload.get("decision", "abort") # "approved" | "revise" | "abort"
    feedback = approval_payload.get("feedback")
    diagnostics = list(state.get("diagnostics", []))
    if feedback:
        diagnostics.append(f"Reviewer feedback: {feedback}")
    return {
        "human_approved": (decision == "approved"),
        "review_decision": decision,
        "diagnostics": diagnostics
    }

def route_review(state: AgentState) -> str:
    """Deterministic routing edge: routes human approval, revision feedback loop, or abort."""
    decision = state.get("review_decision", "abort")
    if decision == "approved":
        return "deliver_stage"
    elif decision == "revise":
        return "generate_stage"
    return END

def node_deliver_stage(state: AgentState) -> Dict[str, Any]:
    """Explicit deterministic delivery node: pushes Git branch, opens PR, and registers Tier 2 lineage/catalog."""
    if not state.get("human_approved", False):
        raise RuntimeError("Delivery attempted without explicit human review approval.")

    bundle_dict = state["contracts"]["dbt_artifact_bundle"]
    bundle = DbtArtifactBundle.model_validate(bundle_dict)

    try:
        # 1. Deterministic Git publication (The Skeleton calling deterministic tools)
        branch_name = f"feat/dbt-models-{state['run_id'][:8]}"
        commit_sha, pr_url = publish_dbt_pull_request(
            repo_uri=settings.destinations.target_git_repo.uri,
            branch_name=branch_name,
            source_dir=bundle.storage_uri,
            files=bundle.file_manifest,
            commit_message=f"feat(dbt): automated dbt pipeline models [run_id: {state['run_id']}]"
        )

        # 2. Transactional Tier 2 Lineage & Catalog Registration (Deterministic DB transaction)
        register_pipeline_delivery(
            metadata_db_uri=settings.METADATA_DB_URI,
            run_id=state["run_id"],
            bundle=bundle,
            commit_sha=commit_sha,
            pr_url=pr_url
        )

        # 3. Emit terminal DeliveryManifest contract into AgentState
        manifest = DeliveryManifest(
            manifest_id=str(uuid.uuid4()),
            run_id=state["run_id"],
            repository=settings.destinations.target_git_repo.uri,
            branch_name=branch_name,
            commit_sha=commit_sha,
            pull_request_url=pr_url,
            artifact_sha256=bundle.artifact_sha256
        )

        return {
            "contracts": {**state["contracts"], "delivery_manifest": manifest.model_dump()},
            "diagnostics": []
        }
    except Exception as e:
        # Surface delivery/Git/DB failure cleanly in state and raise to prevent silent success
        raise RuntimeError(f"Phase 8 Delivery Failed: {str(e)}") from e

def build_graph() -> StateGraph:
    workflow = StateGraph(AgentState)
    workflow.add_node("discover_stage", node_discover_stage)
    workflow.add_node("plan_stage", node_plan_stage)
    workflow.add_node("generate_stage", node_generate_stage)
    workflow.add_node("dry_run_stage", node_dry_run_stage)
    workflow.add_node("review_stage", node_review_stage)
    workflow.add_node("deliver_stage", node_deliver_stage)
    
    workflow.set_entry_point("discover_stage")
    workflow.add_edge("discover_stage", "plan_stage")
    workflow.add_edge("plan_stage", "generate_stage")
    workflow.add_edge("generate_stage", "dry_run_stage")
    workflow.add_conditional_edges("dry_run_stage", route_dry_run)
    workflow.add_conditional_edges("review_stage", route_review)
    workflow.add_edge("deliver_stage", END)
    
    # review_stage uses native interrupt() to serialize state to Postgres checkpointer
    return workflow.compile(
        checkpointer=PostgresSaver.from_conn_string(settings.CHECKPOINTER_DB_URI)
    )

def run_agent(run_id: str, input_profile: Dict[str, Any]):
    """Entrypoint executing the state graph with Tier 1/2 metadata lifecycle callbacks."""
    app = build_graph()
    telemetry_handler = MetadataCallbackHandler(metadata_db_uri=settings.METADATA_DB_URI)
    config = {
        "callbacks": [telemetry_handler],
        "configurable": {"thread_id": run_id}
    }
    initial_state: AgentState = {
        "run_id": run_id,
        "contracts": {"source_schema_profile": input_profile},
        "reflection_count": 0,
        "diagnostics": [],
        "human_approved": False,
        "review_decision": None
    }
    return app.invoke(initial_state, config=config)
```

### 4.2 Strategy 2: Python + LiteLLM (`python_litellm`)

Designed for lightweight, single-turn CLI tools or event-driven webhooks that execute sequentially without requiring checkpoint persistence.

#### Characteristics
- Emits a clean, sequential runner class `src/pipeline.py`.
- Stages execute in topological sequence.
- Uses `@tenacity.retry` for transient API errors.
- Emits a CLI entry point (`src/main.py`) powered by Typer or Click.

```python
# ==============================================================================

import logging

from src.core.config import settings

class LiteLLMAgentRunner:

        self.context: Dict[str, Any] = {"run_id": run_id, "contracts": {}}
```

### 5.2 The Tool Hook Protocol

To wire the Skeleton to the Muscle, the Documentarian declares a bespoke tool in the stage YAML:


### 5.3 Operating Modes & State Projection for the Leaf Coder

To avoid overwriting manual production hotfixes (the "2 AM Hotfix Overwrite" trap), the Leaf Coder operates in one of two distinct modes:

1. **`create` Mode (Day-0 Synthesis)**: Invoked during initial agent construction when `src/tools/<file>.py` does not yet exist on disk. Following the **Context Funnel Principle** ([`architecture.md` Section 5.1](file:///s:/DATA/agents/ddlc-agent-studio/design-docs/meta-agent/architecture.md)), it receives a narrow state projection:
   - Tool signature requirement and hook name (`validate_sql_ast`).
   - Input and Output contract schemas.
   - `processing.logic_description`.
   - *Output*: Emits new tool file and companion unit test from scratch.

2. **`patch` Mode (Day-2 Surgical Mutation)**: Invoked during a Change Request or Rebuild when `src/tools/<file>.py` already exists on disk. To prevent regressing emergency hotfixes, it receives:
   - **Existing Tool Source Code** (`existing_code`) currently committed in `src/tools/`.
   - **Existing Unit Tests** (`existing_tests`) in `tests/unit/`.
   - Updated Input and Output contract schemas.
   - Updated `processing.logic_description` and change request diff.
   - *Behavior*: Acts as a surgical code refactorer. It integrates the requested change while **preserving existing logic, edge-case handlers, and emergency bugfixes**.

The Leaf Coder never sees the global blackboard, unaffected stages, graph orchestration, or conversation history. The prompt remains under 1,800 tokens.

### 5.4 Leaf Coder Output: Tool Code + Unit Test

The Leaf Coder synthesizes isolated, typed Python tools and companion pytest suites:

#### 1. Custom AST Verifier Tool (`src/tools/sqlglot_verifier.py`)
```python
"""
DDLC Custom Tool: validate_sql_ast
Generated by DDLC Leaf Coder. Editable by engineering team.
Stage: generate (tool handler: tools/sqlglot_verifier.py::validate_sql_ast)
"""
import re
from typing import Tuple
import sqlglot
from sqlglot.errors import ParseError

def validate_sql_ast(sql_content: str, dialect: str = "snowflake") -> Tuple[bool, str]:
    """Validates SQL model syntax against target dialect AST using SQLGlot.
    
    Preprocesses dbt Jinja expressions (e.g. {{ source(...) }}, {{ ref(...) }}, {{ config(...) }})
    before AST parsing to avoid false-positive ParseErrors on uncompiled dbt templates.
    """
    # Replace ref() and source() macro calls with dummy identifiers for syntactic AST validation
    sanitized_sql = re.sub(r"\{\{\s*(?:ref|source)\s*\([^}]+\)\s*\}\}", "__dbt_table__", sql_content)
    # Strip dbt configuration blocks
    sanitized_sql = re.sub(r"\{\{\s*config\s*\([^}]+\)\s*\}\}", "", sanitized_sql)
    
    try:
        sqlglot.parse(sanitized_sql, read=dialect)
        return True, ""
    except ParseError as pe:
        return False, str(pe)
```

#### 3. Domain Jinja2 Prompt Templates (The Universal Prompt Contract)

Prompt templates (`src/prompts/*.jinja2`) belong to **The Muscle**: they are synthesized by the Leaf Coder and freely editable by analytics engineers.

The deterministic Skeleton injects an identical, predictable context dictionary into every `llm_reasoning` stage render call:

| Context Variable | Type | Source & Purpose |
|---|---|---|
| `input` | Pydantic Model / Dict | The validated input contract for this stage (e.g. `SourceSchemaProfile`, `TransformationPlan`). Field access (`input.tables` or `input["tables"]`) is fully typed and contract-backed. |

| `feedback` | `List[str]` | List of human reviewer revision requests or instructions captured during human review gates. Empty if no review comments exist. |
| `config` | `Dict[str, Any]` | Non-secret stage parameters, target database dialects, naming conventions, and environment variables compiled from `config.yaml`. |

### 5.5 The "2 AM On-Call Rule" & Preventing the Hotfix Overwrite Trap

Because `src/tools/sqlglot_verifier.py` and `src/prompts/*.jinja2` are standard, isolated files:
1. **Zero Orchestration Risk**: An engineer fixing an edge case at 2 AM does not touch LangGraph edges, checkpointer settings, or metadata emission.
2. **Instant Test Verification**: Running `$ pytest tests/unit/test_sqlglot_verifier.py` takes 50 milliseconds without requiring cloud credentials.
3. **GitOps Friendly**: Changes appear in code reviews as clean, readable 5-line diffs in `src/tools/`.

> [!IMPORTANT]
> **Preventing the "2 AM Hotfix Overwrite" Trap**  
> If an on-call engineer fixes a bug directly in `src/tools/sqlglot_verifier.py` without updating `stage_generate.yaml`, there is a risk that a future Meta-Agent change request could regenerate the tool from the old YAML description and silently overwrite the hotfix.
> 
> The DDLC architecture eliminates this risk through two cooperating safety mechanisms:
> 1. **Leaf Coder `patch` Mode**: During Day-2 change flows, the Leaf Coder inspects the existing `src/tools/sqlglot_verifier.py` code directly. It applies mutations surgically rather than regenerating from scratch, retaining the bugfix.
> 2. **CI Drift Detection (`ddlc check-drift`)**: A CI workflow checks if a PR modifies `src/tools/` without modifying `impl_docs/stages/`. If drift is detected, CI issues an advisory check:  
>    `[DRIFT-WARNING] src/tools/sqlglot_verifier.py was modified without updating stages/stage_generate.yaml.`  
> 3. **Post-Incident Doc Sync (`ddlc sync-docs`)**: After incident resolution, the developer runs `$ ddlc sync-docs` (or lets the Spec Analyst reverse-sync). The tool reads the tool's updated logic/docstring and synchronizes `stage_generate.yaml` (`processing.logic_description`), restoring complete documentation-to-code alignment.

### 8.1 Prompt Template AST & Interface Validation

To guarantee that templates authored or patched by the Leaf Coder (The Muscle) never crash the deterministic StateGraph runtime (The Skeleton), the Validator performs static AST analysis using `jinja2.meta.find_undeclared_variables()` prior to execution:

```python
import jinja2
import jinja2.meta
from typing import List, Set

ALLOWED_PROMPT_CONTEXT_VARS: Set[str] = {"input", "diagnostics", "feedback", "config"}

def validate_prompt_template_ast(template_path: str, template_source: str) -> List[str]:
    """Statically validates Jinja2 template AST against the Universal Prompt Contract.
    
    Guarantees that the editable Muscle (prompts/*.jinja2) only references variables
    provided by the deterministic Skeleton context, eliminating runtime UndefinedError crashes.
    """
    env = jinja2.Environment()
    try:
        parsed_ast = env.parse(template_source)
    except jinja2.TemplateSyntaxError as e:
        return [f"Syntax error in '{template_path}' at line {e.lineno}: {e.message}"]

    undeclared_vars = jinja2.meta.find_undeclared_variables(parsed_ast)
    illegal_vars = undeclared_vars - ALLOWED_PROMPT_CONTEXT_VARS

    errors = []
    if illegal_vars:
        errors.append(
            f"Prompt template '{template_path}' references undeclared variables: {sorted(list(illegal_vars))}. "
            f"Templates must strictly conform to the Universal Prompt Contract: {sorted(list(ALLOWED_PROMPT_CONTEXT_VARS))}."
        )
    return errors
```

If a prompt template references illegal variables (e.g. `{{ source_profile }}` or `{{ custom_arg }}`), the Validator produces deterministic fix instructions routing back to the Leaf Coder before any model calls or container deployments occur.

### 8.2 Surgical Fix Loop

If a unit test in `tests/unit/test_sqlglot_verifier.py` fails:
- The Validator produces specific error diagnostics (e.g., `AssertionError: validate_sql_ast returned False for valid CTE`).
- The Coordinator routes **strictly to the LLM Leaf Coder** with the failure log.
- **The Scaffold Compiler is NOT re-run**. The Skeleton remains intact.
- The Leaf Coder patches `src/tools/sqlglot_verifier.py` and returns it to the Validator.
- Maximum fix attempts (default: 3) are enforced by the coordinator safety valve.

## 9. Day-2 Lifecycle & Maintenance (Change Requests & Hotfixes)

In production, agents evolve. The separation between Skeleton and Muscle enables clean, risk-free Day-2 maintenance.

### 9.1 Scenario A: Schema Evolution or Graph Re-wiring
- **Trigger**: A developer adds a new column to `contracts/source_schema_profile.yaml` or updates a retry threshold in `stages/stage_plan.yaml` via Pull Request.
- **Action**: CI runs the **Deterministic Scaffold Compiler**:
  - `src/models/contracts_pydantic.py` and `src/graph.py` are deterministically re-emitted in 100ms.
  - Existing custom tools in `src/tools/` and prompt templates in `src/prompts/` are **untouched**.
  - Zero LLM tokens spent.

### 9.2 Scenario B: Imperative Tool Hotfix (The 2 AM Patch)
- **Trigger**: An engineer discovers that `sqlglot_verifier.py` fails on a specific Snowflake-specific syntax extension (e.g., `QUALIFY ROW_NUMBER() OVER (...) = 1`).
- **Action**: An on-call engineer opens `src/tools/sqlglot_verifier.py`:
  - Adds dialect configuration handling for `QUALIFY`.
  - Updates the corresponding test assertion in `tests/unit/test_sqlglot_verifier.py`.
  - Runs `$ pytest tests/unit/` locally. Tests pass in <50ms.
  - Commits directly to Git.
  - **CI Drift Check**: CI executes `ddlc check-drift` and detects that `src/tools/sqlglot_verifier.py` was altered without touching `stages/stage_generate.yaml`. It passes the emergency build with an advisory warning:  
    `[DRIFT-WARNING] Tool modified without stage doc update. Run 'ddlc sync-docs' post-incident.`
  - **Post-Incident Sync**: After the incident is resolved, running `$ ddlc sync-docs` updates `stage_generate.yaml` (`processing.logic_description`), restoring complete single-source-of-truth alignment.

### 9.3 Scenario C: Conversational Feature Addition via Meta-Agent (Patch Mode Safety)
- **Trigger**: User prompts Meta-Agent: *"Add semantic layer metric declarations to the generated dbt models"*.
- **Action**:
  - Spec Analyst and Documentarian update `contracts/dbt_artifact_bundle.yaml` and `stages/stage_generate.yaml`.
  - Deterministic Compiler updates `src/models/contracts_pydantic.py`.
  - **Leaf Coder in `patch` Mode**: Because `src/tools/sqlglot_verifier.py` already exists, the Leaf Coder runs in `patch` mode. Its projected context includes the change request AND the existing code. It surgically updates prompt templates while **preserving all existing dialect hotfixes from Scenario B**, completely averting silent regression.
  - Validator checks the entire agent and executes all unit tests. Done.

## 10. Design Decisions Log (Builder Scope)

All architectural decisions governing the Builder Specialist are recorded below:

| # | Architectural Decision | Selected Approach | Alternative Rejected | Rationale |
|---|---|---|---|---|
| **B-1** | **Scaffold Generation Engine** | Deterministic Jinja2 + Python AST Compiler | All-LLM code generation from prompts | Guarantees 100% syntax determinism, zero hallucinations on graph wiring or data contracts, and sub-second execution with zero token cost. |
| **B-2** | **Imperative Logic Generation** | Isolated LLM Leaf Coder with narrow State Projection | Hardcoded rule templates or monolithic generation | Complex tools (inspectors, verifiers, parsers) cannot be expressed cleanly in YAML; LLM excels at writing isolated leaf functions when constrained by contracts. |
| **B-3** | **Read-Only Code Boundary** | `# DO NOT EDIT` immutable headers + CI AST checksums | Allowing freehand editing of generated graph code | Prevents drift between `impl_docs/` and the underlying runtime state machine. `impl_docs/` remains the single source of truth. |
| **B-4** | **Hook Dispatch Mechanism** | Explicit YAML tool hook (`processing.tools[].handler: "tools/mod.py::func"`) | Magic class inheritance or implicit file naming | Explicit string import paths on declared custom tools are transparent, easily statically validated by `ast.parse`, and allow arbitrary naming conventions. |
| **B-5** | **Contract Implementation** | Pydantic v2 / Instructor Data Models (`contracts_pydantic.py`) | Dual-compilation with Pandera or raw dicts | Layer 2 AI agents operate on structured engineering artifacts and LLM outputs, not bulk 500k-row data batches. Pydantic v2 compiles cleanly and powers Instructor structured output validation. |
| **B-6** | **Runtime Portability** | Modular strategy templates (`langgraph`, `python_litellm`) | Single universal runtime | Different DDLC agents have different interaction models (stateful graph with tool loops & gates vs. lightweight CLI runner); strategy isolation allows adding new runtimes cleanly without touching YAML specs. |
| **B-7** | **Fix Loop Granularity** | Surgical re-prompting of Leaf Coder for tool test failures | Rebuilding the entire agent from scratch | Eliminates wasted computation and avoids accidental regressions in working stages during fix iterations. |
| **B-8** | **Graph State & Artifact Management (Claim Check)** | Pass Typed Contracts in `AgentState` + Claim Check for large file bundles | Storing multi-megabyte artifact files directly in graph memory | Keeps PostgreSQL checkpointer snapshots sub-millisecond while passing lightweight pointers (`bundle_id`, `uri`, `artifact_sha256`) for large generated repositories. |
| **B-9** | **Agentic Processing Paradigms** | Explicit `processing_type: llm_reasoning \| deterministic_tool \| human_gate` | Layer 3 data execution modes (`batch`, `chunked`, `row`) | Retires bulk data processing paradigms. Distinguishes between LLM reasoning (model tiers, Instructor output schemas), deterministic tool execution (`@tool` bindings), and human review gates. |
| **B-10** | **Leaf Coder Operating Modes & Drift Reconciliation** | `create` for Day-0 synthesis, `patch` for Day-2 refactoring with existing code context + CI drift warnings & `ddlc sync-docs` | Blind regeneration of tool files on Day-2 | Eliminates the "2 AM Hotfix Overwrite" trap where conversational change requests regenerate files from YAML descriptions and silently wipe out emergency production hotfixes. |
| **B-11** | **Layer 2 DDLC AI Agent Synthesis** | Canonical agent: `dbt_pipeline_builder_agent` | Modeling Layer 3 data pipelines (`customer_data_pipeline`) | Aligns Builder specialist with the Meta-Agent's core purpose: building AI agents that build, modify, and operate data pipelines. Skeleton emits LangGraph DAG, LiteLLM client config, and Instructor schemas; Leaf Coder emits agentic tools and prompt templates. |
| **B-12** | **Universal Prompt Contract & Static AST Validation** | Standardized 4-key context (`input`, `diagnostics`, `feedback`, `config`) + `StrictUndefined` + `jinja2.meta.find_undeclared_variables()` AST lint | Ad-hoc per-node render kwargs or permissive jinja undefined behavior | Eliminates runtime `UndefinedError` crashes when prompt templates are regenerated or hand-edited; strictly decouples Skeleton orchestration from Muscle prompts through a verified compile-time interface. |
